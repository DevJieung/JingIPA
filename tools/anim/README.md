# tools/anim — 마스터 한 장에서 Idle · Attack · Shot 을 짠다

절차의 **왜**는 [`docs/ART.md`](../../docs/ART.md) 에 있다. 여기는 **어떻게 돌리는가**다.
`build/firewiz/`(화염마도사를 만들며 쓴 일회용 스크립트)를 일반화해 옮긴 것이고,
지금까지 화염마도사 · 서리여왕 · 뇌전궁수 셋을 이걸로 만들었다.

```
concepts.json   캐릭터마다 컨셉 · 등급 · 이펙트 램프 · 무기 · 이웃(=1:1 로 대조할 캐릭터)
gen_master.py   후보 N장            (AI 는 여기서만 쓴다)
contact.py      후보 + 같은 속성 캐릭터를 1:1 로 한 판에
probe.py        격자·십자를 얹어 어깨 · 손끝 · 소품 자리를 눈으로 찍는다
deffect.py      손 위의 이펙트만 떼기 (덩어리는 물로 · **막대는 선으로**)
cut_arm.py      몸통 / 팔 가르기 → part_torso.png · part_arm.png · rig.json
rig.py          팔을 어깨 축으로 돌리는 뼈대 (mkanim 이 import 한다)
fx.py           이펙트 그리기 — 램프 색으로만, 반투명 없이
mkanim.py       동작 표대로 짜고 검사한다
```

## 캐릭터를 정하는 손잡이

속성 하나가 전부를 정하지 않는다. **무기**가 따로다 (ART.md 「세 번째 캐릭터」).

| `concepts.json` | 무엇을 정하나 | 값 |
|---|---|---|
| `facets` | 이펙트의 심과 가지 | `0` 불 · `6` 얼음 · `-1` 전기 |
| `shot`   | 날아가는 것 | `bolt`(기본) 덩어리 · `arrow` 살대+살촉+깃 |
| `muzzle` | 탄이 나가는 자리 | `hand`(기본) 마법사 · `prop` 활·총 |
| `link`   | 손과 소품을 잇는 것 | `wobble`(기본) 흐르는 부스러기 · `shaft` 메긴 살 |
| `motion` | 동작 표 | `cast`(기본) 던지기 · `draw` 쏘기 |
| `stretch`| 팔 길이 배수 한계 | 기본 `0.80,1.35` |
| `holes`  | 갇힌 배경을 지울지 | **활 캐릭터는 `true`** |

전부 `mkanim.py`/`gen_master.py` 의 같은 이름 인자로도 덮어쓸 수 있다.

## 새 캐릭터 하나 만들기

**1. `concepts.json` 에 항목을 더한다.** 몸통 묘사만 적는다 — 화풍·구도·배경 문구는
`tools/gen_art.py` 의 앵커가 붙인다. 컨셉에 셋을 반드시 넣는다(ART.md 0):
한쪽 팔을 앞으로 뻗은 3/4 정면 · **소품은 반대 손** · 뻗은 손 위 이펙트 하나.
★ **활·총은 예외다** — 아래 ★ 를 봐라.

```bash
python3 tools/anim/gen_master.py <id> --seeds 3     # 컨셉 3 x 시드 3 = 9장, 약 14분
python3 tools/anim/contact.py    <id>               # 이웃과 1:1 로 나란히 놓고 눈으로 고른다
cp build/<id>/cand/<고른것>.png build/<id>/master.png
```

★ **활 · 총처럼 소품에서 탄이 나가는 캐릭터는 자세를 다르게 적는다** (ART.md 0).
「한쪽 팔을 앞으로 뻗은 3/4 정면」으로 적으면 소품이 **몸 뒤로** 간다 — 궁수에서 아홉 장이
전부 그랬다. 「소품을 앞으로 내밀고 겨눈다」로 적어라. 갈래마다 자세를 따로 줄 수 있다:

```json
"poses": {"d": ", in a three-quarter side view, aiming the bow across the frame, both arms out in front"}
```
```bash
python3 tools/anim/gen_master.py <id> --only d,e,f --seeds 3 --holes   # 그 갈래만 다시
```

**고르는 기준**(ART.md 2): ① `(sat<=22 & val>=205)` 흰 픽셀이 **얼굴·하이라이트에**
걸려 있으면 탈락 ② 등급 높이에서 실루엣이 읽히는가 ③ 같은 속성 캐릭터와 **1:1 로
나란히** 놓고 안 겹치는가. 혼자 보면 늘 괜찮아 보인다.

★ 등급(=저장 높이)은 후처리에서만 쓴다. 바꾸고 싶으면 GPU 를 다시 안 돌려도 된다:
`gen_master.py <id> --repost --tier 8`

**2. 손 위의 이펙트를 뗀다.**

```bash
python3 tools/anim/deffect.py build/<id>/master.png build/<id>/master_body.png \
        --box 0.68,0.0,1.0,0.34 --hue cool     # warm=불·용암 · cool=얼음·물
```

★ **막대(살 · 창 · 광선)는 물로 못 뗀다** — 색이 손등과 같고 손·소품에 이어져 있다.
양 끝을 찍어서 **선으로** 뗀다. `x0,y0,x1,y1,굵기` 를 `;` 로 여럿:

```bash
python3 tools/anim/deffect.py build/<id>/master.png build/<id>/master_body.png \
        --line "28,44,45,44,1;46,44,67,44,3;79,44,90,44,7;27,44,14,33,4"
```
★ **몸 위를 지나는 대목은 1px**, 배경 위는 3px 처럼 나눠 뗀다. 얼굴 앞을 지나는 살을
3px 로 뗐더니 뺨에 구멍이 뚫려 놓는 칸마다 머리가 잘려 보였다.
★ 덩어리인데 안 갈리면 `--seed x,y`(심지를 직접 찍는다)와 `--lo 0.40`(문턱 시작점을
낮춘다)을 써라. `--keep-floating` 은 몸에서 떨어진 **소품 조각**이 있는 그림에 쓴다.

**3. 뼈대 점을 찍고 몸통/팔을 가른다.**

```bash
python3 tools/anim/probe.py build/<id>/master_body.png 55,46 12,72 4,34
python3 tools/anim/cut_arm.py build/<id>/master_body.png \
        --shoulder 55,46 --cut 56@38,60@78 --yrange 38,78 --tip 80,42 --out build/<id>
```

★ **결과물이 out/ 에 있으면 파이프라인을 다시 돌릴 때 지워진다.** 문서를 out/ 에 두면
같이 날아간다 — 실제로 한 번 날렸다.

★ `--tip` 은 **손끝**이다. 안 주면 「어깨에서 가장 먼 팔 픽셀」을 쓰는데, 자락이 길게
드리운 팔에서는 그게 **자락 끝**을 집는다(서리여왕이 실제로 그랬다).
그 다음 `build/<id>/rig.json` 에 `prop_grip`(소품 쥔 손) · `prop_tip`(소품 결정)을 적는다.
★ **활에서 `prop_tip` 은 활 끝이 아니라 「살이 얹힌 자리」다** — 그게 곧 총구다.
윗고자로 찍었더니 화살이 활 꼭대기에서 튀어나와 얼굴을 가로질렀다.
★ 팔이 **왼쪽을 보는** 캐릭터(만작 궁수)는 `--side left` 다. 자르는 선을 얼굴 쪽으로
너무 붙이면 **턱이 팔에 딸려 가서** 놓는 칸마다 머리가 잘려 보인다.

**4. 프레임을 짠다.**

```bash
python3 tools/anim/mkanim.py <id> --src build/<id> --lift=-5,-16 --fx 1.30
```

- `--lift dx,dy` — 이펙트를 손끝에서 어디에 놓을지. **마스터에서 이펙트가 손바닥 위에
  떠 있었으면 그 자리를 그대로 적어라.** 아이들이 정지 그림과 달라 보이는 것이 여기서 온다.
- `--fx` — 이펙트 크기 배수. 등급이 큰 캐릭터는 1.2~1.4. 칸 여백도 같이 커진다.

## 동작 표

`mkanim.py` 위쪽의 `MOTIONS` · `IDLES` 다 (`cast` 마법사 · `draw` 궁수). 손 목표를 **마스터 픽셀로 적지 마라** —
캐릭터가 바뀔 때마다 열 줄을 다시 재야 하고, 0 번 칸이 마스터와 1px 이라도 어긋나면
아이들이 정지 그림과 달라진다. 네 가지로 적는다:

| | |
|---|---|
| `("rest",)` | 제자리 — **손을 아예 안 건드린다.** 0·9 번과 아이들이 쓴다 |
| `("arm", 각도차°, 길이배수)` | 제자리에서 그만큼 돌린다. 음수가 위쪽 |
| `("toward", 길이배수, 각도차°)` | **소품 쪽으로** 그만큼 뻗는다 (손이 소품에 안 닿는 캐릭터) |
| `("prop", dx, dy)` | 소품 잡은 자리에 손을 댄다 |

★ **짧은 팔은 각도로 짜라.** 만작 궁수는 어깨~손이 10px 이라(마법사 34px) 길이 배수를
30% 바꿔도 손이 3px 움직이고 그건 안 보인다. 팔꿈치는 어깨에서 27px 이라 24도만 돌려도
11px 간다.
★ `draw` 표는 **놓은 다음 칸의 시위를 비워 둔다**(`shaft` 를 안 적는다). 바로 다시 메면
「쐈는데 그대로 있다」로 보인다 — 이 동작에서 제일 크게 읽히는 사건이 그것이다.

## 검사 (mkanim 끝)

넷을 본다. 하나라도 걸리면 0 이 아닌 값으로 끝난다.

1. **반투명 0개** — 이 게임의 그림은 알파가 0/255 뿐이다
2. **색 수** 예산 안
3. **마스터 팔레트를 벗어난 색 0개** — 벗어났으면 어딘가에서 색을 섞은 것이고,
   그건 곧 시트를 다시 양자화해야 한다는 뜻이다 (그 양자화가 옷 색을 탁하게 만든다)
4. **칸 밖으로 잘린 프레임 0개** — 이펙트를 키우면 마지막 칸의 탄이 조용히 잘린다.
   스트립만 보면 안 보이고 게임에서 「탄이 반쪽」으로 나온다.
   ★ 칸 크기는 못 박지 않는다. 넉넉히 그려 놓고 **안 잘리는 가장 작은 칸으로 줄인다**
   (`fit_cell`). 좌우를 같은 만큼 두므로 기준점은 그대로 가로 가운데 · 세로 발밑이다.

## 되돌림 시험

도구를 고쳤으면 **화염마도사가 그대로 나오는지** 본다.
★ 궁수를 만들며 `rig.plan` 의 뒤집기 규칙과 `fx.shape` 의 가지 셈을 일반화했는데,
이 시험이 **픽셀 단위로 같음**을 확인해 줬다(서리여왕은 파일 해시까지 같았다).

```bash
mkdir -p build/regress && cp build/firewiz/part_torso.png build/firewiz/part_arm.png build/regress/
cp build/firewiz/cand/a1.png build/regress/master.png
cat > build/regress/rig.json <<'JSON'
{"shoulder":[55,31],"tip":[89,32],"prop_grip":[15,50],"prop_tip":[8,15]}
JSON
python3 tools/anim/mkanim.py blaze_wizard --src build/regress
```

45색 · 반투명 0 · 팔레트이탈 0 · **잘림 0** · 칸 **204x127** 이 나와야 한다.
(공격 칸에도 `fx_at` 을 걸기 전에는 204x129 였다 — ART.md 「세 번째 캐릭터」 참조.
서리여왕은 216x158 → 214x150 이다.)
(옛 도구는 175x131 로 못 박혀 있었고 7·8 번 칸의 불덩이가 오른쪽에서 잘려 있었다)
★ 프레임 표를 극좌표로 옮기며 반올림이 생겨 옛 결과와 **0.6~0.7% 픽셀**이 다르다.
그보다 크게 벌어지면 무언가 깨진 것이다.
