# 데미지를 눈으로 따라가기

「이 한 대가 왜 이 숫자인가」를 보는 법. 두 갈래다.

| | 무엇 | 언제 |
|---|---|---|
| **A. 에디터에서 플레이하며** | 게임 안의 **디버그 오버레이(F3)** · 에디터의 중단점 · 원격 씬 트리 | 손으로 해 보면서 흐름을 볼 때 |
| **B. 헤드리스로** | `tests/dmg_check` — 곱셈 사슬 · 전투 추적 · 자체 검사 | 숫자를 재고 어긋남을 자동으로 잡을 때 |

---

# A. 데탑에서 에디터로 보기

## A-1. 프로젝트 열기

Godot **4.7** 대가 필요하다(`project.godot:21` `config/features=PackedStringArray("4.7", "GL Compatibility")`; 이 저장소는 4.7.1 로 돌리고 있다). 에디터에서 이 폴더를
import 하고 **F5** 로 실행하면 된다. 명령줄이면:

```bash
godot -e --path .        # 에디터
godot --path .           # 그냥 실행
```

그림·소리는 **저장소에 들어 있다**(`art/`). 따로 만들 필요 없다 — 없어도 게임은 돌지만
(코드가 색 도형으로 대신 그린다) 그러면 보고 싶은 화면이 안 나온다.

★ **게임 코드는 명령줄을 안 읽는다**(CLAUDE.md 19). 그래서 에디터에서 그냥 실행해도
검사기·촬영 도구의 인자와 부딪히지 않는다.

## A-2. 디버그 오버레이 — F3

전투 화면에서 **F3** 를 누르면 판이 하나 뜬다. **에디터에서 플레이하면서 보라고** 만든
것이고, 폰(터치)에는 자리를 하나도 안 내준다 — 안드로이드에서는 켜질 일이 없다.

```
 F3        켜기 / 끄기
 Tab       탭 넘기기
 1 ~ 6     곱셈 사슬을 펼쳐 볼 영웅 고르기
 스페이스    전투 멈춤 / 재개
 마침표     멈춘 채로 한 걸음만 (1/60초)
```

**멈춤과 한 걸음이 이 도구의 핵심이다.** 초당 수백 번 일어나는 일을 눈으로 볼 방법은
그것뿐이다 — 스페이스로 세워 놓고 마침표로 한 프레임씩 밀면서, 탄이 닿는 순간 어느
줄이 새로 생기는지 본다.

### 탭 넷

| 탭 | 보이는 것 |
|---|---|
| **흐름** | **hp 가 깎인 것 전부**를 새것부터 위로. `시각 · 경로 · 누가 · 누구를 · 몸 · 요청 · x상성 · 실제 차감 · 남은 hp`. 맨 윗줄에 경로별 누적(직격/광역/연쇄/광선/장판/화상/패시브)과 **헛방(면역) 횟수** |
| **영웅** | 성역 여섯의 실시간 값(한 발 세기·초당 발·겹침·누적 피해·처치) + 고른 하나의 **곱셈 사슬 여덟 줄**, 그리고 그 한 발이 다섯 몸에 각각 얼마로 들어가는지 |
| **몬스터** | 지금 살아 있는 놈들 — 체력 막대 · **상태이상 남은 초** · 길을 온 만큼 |
| **표** | 상성 5x5 · 이번 탄에 오는 놈과 약점/면역 · 성역에 선 영웅의 속성 |

**「헛방 N번」이 이 판에서 가장 값어치 있는 한 줄이다.** 전기 영웅을 세워 놓고 나무나
바위 몬스터가 오는 탄이면 이 수가 수십 번씩 오른다 — 클리어율로는 절대 안 보이고, 화면의
「무효」 글자는 한 번에 하나씩만 스쳐 지나간다.

★ 오버레이가 꺼져 있으면 **값도 속도도 예전과 한 톨도 안 다르다.** `DbgSim` 의 override
들이 첫 줄에서 `if not Dbg.on:` 으로 곧장 빠지고, 자동 플레이 검사(`balance_check`)는
아예 `BattleSim` 을 그대로 만든다.

## A-3. 중단점 — 한 대를 통째로 멈춰 세우고 보기

에디터에서 줄 번호 왼쪽을 클릭하면 중단점이다. 걸 만한 자리는 넷뿐이다.

| 무엇을 보고 싶나 | 어디 | 그 자리에서 보이는 것(디버거 > 스택 변수) |
|---|---|---|
| **한 발의 세기가 다 만들어진 뒤** | `core/run.gd:757` `hero_stats()` | `u` `t` `prof` `bul` `el` `n` `atk` `rate` — 곱셈 사슬의 항이 전부 지역 변수다 |
| **쏘기로 정하는 순간** (치명타가 굴려진다) | `game/battle_sim.gd:387` | `he` `crit` `dmg` `am` — 여기 `dmg` 가 곧 탄에 실리는 값 |
| **★ hp 가 깎이는 순간** | `game/battle_sim.gd:785` (`dmg *= em`) | `mo` `body` `em` `dmg` — **게임에서 hp 가 깎이는 곳은 여기 하나뿐이다** |
| **상태이상이 붙는 순간** | `game/battle_sim.gd:826` `_apply_rider()` | `elem` `dmg` — 얼음/불/전기 갈래로 나뉘기 직전 |

★ **매 대마다 멈추면 못 쓴다.** 초당 수백 번이다. GDScript 에는 **`breakpoint` 키워드**가
있으니, 보고 싶은 조건에만 걸어라 — 한 줄 넣었다 지우면 된다:

```gdscript
	var em: float = Balance.elem_mult(elem, body)
	if elem == "elec" and body == "rock":    # 전기가 바위를 때리는 순간에만
		breakpoint
```

★ 중단점을 걸어 두면 `tools/verify.sh` 가 헤드리스로 돌 때 거기서 멈춰 버린다. **커밋
전에 지워라.**

## A-4. 원격 씬 트리 — 변수를 실시간으로

실행 중에 에디터 아래 **디버거 > 원격**(Remote) 탭에서 노드를 고르면, 인스펙터에 그
노드의 스크립트 변수가 **실시간으로** 뜬다. 화면 이름이 그대로 보인다(`BattleScreen` ·
`DrawScreen` · `ShopScreen` …).

`BattleScreen` 을 고르면 볼 만한 것: `speed` · `t` · `_dps` · `ended` · `_crack_t`.
`sim`(BattleSim)은 RefCounted 라 인스펙터에서 눌러 들어가면 `monsters` · `bullets` ·
`heroes` · `elapsed` · `leaked` 배열을 그대로 펼쳐 볼 수 있다.

★ 다만 **배열 안을 초당 60번 갱신해 보여 주지는 않는다.** 「지금 이 순간의 값」을
정확히 보려면 스페이스로 멈추고(오버레이) 나서 인스펙터를 봐라.

## A-5. 그 밖에 에디터가 주는 것

- **디버거 > 모니터** — FPS · 드로우 콜 · 물체 수. 후반 탄에서 몬스터 40마리 + 탄
  200개가 도는 동안 프레임이 떨어지는지 볼 때.
- **출력(Output)** — `print` 가 여기 뜬다. 다만 **게임 코드에는 박지 마라**(A-6).
- **디버그 > 보이는 충돌 도형** — 이 게임에는 쓸 데가 없다. 물리 노드를 하나도 안 쓴다
  (몬스터·탄은 전부 `BattleSim` 안의 Dictionary 다).

## A-6. 왜 게임 코드에 print 를 박지 않는가

`game/battle_sim.gd` 는 자동 플레이 검사가 **100탄을 수십 번** 돌리는 코드다. 거기에
`print` 하나를 박으면 검사가 초당 수천 줄을 뱉어 몇 배로 느려지고, 지우는 것을 잊으면
APK 에 그대로 실린다.

대신 **`BattleSim` 을 물려받아 가로챈다.** GDScript 는 메서드가 전부 가상이라 부모 안에서
부른 `_hurt()` 도 자식의 override 로 온다:

```gdscript
class_name DbgSim extends BattleSim

func _hurt(mi, dmg, _crit, _src, elem, rider, rider_dmg, rider_n, flash) -> float:
    if not Dbg.on:
        return super(mi, dmg, _crit, _src, elem, rider, rider_dmg, rider_n, flash)
    var hp0 := float(monsters[mi]["hp"])
    var em := super(mi, dmg, _crit, _src, elem, rider, rider_dmg, rider_n, flash)
    Dbg.push({..., "req": dmg, "em": em, "got": hp0 - float(monsters[mi]["hp"])})
    return em
```

이 한 조각으로 **모든 차감**이 잡힌다 — 광역의 둘레 · 연쇄의 두 번째 홉 · 분열 조각 ·
장판처럼 사건(`events`)을 안 흘리는 자리까지. 새로 보고 싶은 것이 생기면
`game/dbg_sim.gd` 에 override 를 **하나 더** 얹어라.

파일 셋이 전부다 — `core/dbg.gd`(상태) · `game/dbg_sim.gd`(담기) · `game/debug_view.gd`(그리기).

# B. 헤드리스로 재기

밸런스 검사(`tests/balance_check`)는 **몇 탄까지 갔나**만 말한다. 그런데 숫자가 이상할 때
알고 싶은 것은 그게 아니라 **이 한 대가 왜 이 숫자인가**다. `tests/dmg_check` 가 그 자리다.

```bash
POCKER_NO_SAVE=1 stdbuf -oL ~/.local/bin/godot --headless --path . \
    res://tests/dmg_check.tscn -- <모드> <옵션>
```

| 모드 | 무엇을 보나 | 얼마나 걸리나 |
|------|-------------|---------------|
| `--calc` (기본) | 한 대의 **곱셈 사슬**을 줄줄이 편다 | 3초 |
| `--trace` | 실제 전투 한 탄을 돌려 **hp 가 깎이는 것을 전부** 찍는다 | 10~30초 |
| `--selftest` | 산수와 실제 전투가 **같은 값**인가 (`판정: 정상`) | 약 5분 |
| `--table` | 상성표 · 탄 방식 · 등급별 화력 · 체력 곡선 | 3초 |
| `--list` | 캐릭터 / 몬스터 / 패시브 **id 목록** (`--unit` 에 넣을 것) | 3초 |

`--help` 로 전체 옵션이 나온다.

## 1. 데미지가 지나가는 길 — 다섯 마디

숫자가 이상하면 **이 다섯 중 어느 마디에서 틀어졌는지**부터 좁힌다. `--calc` 의 출력이
정확히 이 순서로 찍힌다.

| # | 어디서 | 무엇이 곱해지나 |
|---|--------|-----------------|
| 1 | `core/run.gd` `hero_stats()` | 등급 · 성향 · 탄 방식 · **속성 기본화력** · 공명 · 겹침 한 발 몫 · 상점 · 패시브 → **한 발의 세기** |
| 2 | `game/battle_sim.gd` `_heroes_fire()` | `x _atk_mult()`(선제 패시브) · `x critx`(치명타 굴림) → **쏘기로 정한 값** |
| 3 | `_aim()` → `_release()` → `_shoot()` | 값은 안 바뀐다. **팔을 뻗는 시간(`wind`)만큼 늦게** 탄이 뜨고, 겹친 만큼(`shots`) **발이 여러 개** 나간다 |
| 4 | `_impact()` / `_splash()` / `_chain()` / beam / aura | 방식마다 `_hurt()` 를 **몇 번, 얼마로** 부르는지가 갈린다 (아래 표) |
| 5 | **`_hurt()`** | `x 상성` → (면역이면 여기서 끝) → `x 거인사냥` → `x 과잉살상` → **`hp -= dmg`** → 상태이상 |

★ **hp 가 깎이는 곳은 `_hurt()` 한 군데뿐이다.** 딱 하나 예외가 **화상 도트**로,
`_move_monsters()` 가 `hp` 를 직접 깎는다(상성은 `_burn()` 이 붙일 때 미리 곱해 둔다).
`--trace` 는 그 예외까지 잡아서 「화상」 경로로 따로 찍는다.

### 4번 마디 — 방식마다 `_hurt()` 가 몇 번 불리나

| 방식 | 한 번 쏠 때 | 한 번의 값 |
|------|-------------|------------|
| 단발 `shot` | 1번 | `dmg` |
| 관통 `pierce` | 꿴 마릿수만큼 | 매번 `dmg` (감쇠 없음) |
| 광역 `splash` | 1 + 반경 안 마릿수 | 직격 `dmg`, 둘레는 `dmg x falloff(0.7)` |
| 연쇄 `chain` | 1 + 튄 횟수 | 직격 `dmg`, 다음 홉마다 `x decay(0.65)` 누적 |
| 광선 `beam` | 겹친 수만큼(앞선 놈 여럿) | 매번 `dmg` |
| 장판 `aura` | **매 프레임 x 살아 있는 전부** | `dps x dt` — 상태이상만 0.25초 틱에 |
| 패시브 분열 | 모든 명중마다 추가 1회 이상 | `dmg x 0.35` |

★ 그래서 `Run.total_dps()`(단일 대상)는 광역·연쇄·장판을 **과소평가한다.** 어림수로만 써라.

### ★ 광선만 겹침 규칙이 다르다 — 실측

CLAUDE.md 14-5 는 「겹치면 단일 대상 피해가 정확히 n배」라고 적어 두었고 `ns_check` 도
그것을 지킨다. 그런데 그 검사는 **산수**(`stack_atk(n) x stack_shots(n) == n`)만 본다.
그 식은 「n 발이 **같은 놈**에게 간다」를 전제로 하는데, `_shoot()` 의 광선 갈래는
`_nearest_targets(n)` 으로 **서로 다른 n 마리**를 꿴다(같은 놈을 네 번 지지면 화면에서
한 줄기로 보여 겹친 것이 안 읽힌다는 까닭이 코드 주석에 있다).

`--selftest` 7번이 몬스터를 **하나만** 세워 놓고 잰 값:

| 캐릭터 | 방식 | x1 | x4 | 실제 배수 |
|---|---|---|---|---|
| 불씨견습 | 단발 | 27.5 | 110.0 | **x4.00** |
| 짚신궁수 | 관통 | 46.2 | 184.8 | **x4.00** |
| 물지게꾼 | 광역 | 24.7 | 98.8 | **x4.00** |
| 방울무당 | 연쇄 | 145.2 | 580.8 | **x4.00** |
| **태양사제** | **광선** | 463.4 | 463.4 | **x1.00** |
| 화염신관 | 장판 | 92.1 | 368.3 | **x4.00** |

한 대상에 대한 광선의 배수는 `n` 이 아니라 **`stack_atk(n)`** 이다 — `n <= 5` 면 그냥 **1.00**,
`n = 8` 이면 1.60. 여럿이 몰려 있으면 총 피해는 n배가 맞지만, **혼자 오는 보스 앞에서는
겹친 값어치가 통째로 없다.** 그런데 `Run.total_dps()` 는 `x shots` 로 세므로 상점의 「초당
피해」와 자동 플레이 정책은 겹친 광선 영웅을 **n배로 과대평가**한다. 보스가 크리스탈을
셋이나 부수는 게임에서(CLAUDE.md 17) 이건 작은 어긋남이 아니다.

★ 규칙을 바꿀지 표시를 고칠지는 밸런스 결정이라 **손대지 않았다.** `--selftest` 7번이
지금 값을 기대값으로 못 박아 두었으니, 어느 쪽으로 바꾸든 그 줄이 먼저 알려 준다.

## 2. 실전 — 증상별로 어디부터 보나

### 「이 캐릭터 한 대가 왜 이 숫자지」

```bash
POCKER_NO_SAVE=1 ~/.local/bin/godot --headless --path . res://tests/dmg_check.tscn -- \
    --calc --unit blaze_wizard --n 4 --wave 30 --rank 3 --mkind tank \
    --lv atk=6,crit=4,critx=3 --pas heavytip,keenedge --crit
```

곱셈 사슬이 항목마다 한 줄씩, **누적곱과 함께** 나온다. 마지막 줄이
`hero_stats()["atk"]` 와 나란히 찍히고 **어긋나면 「!! 어긋남」**이 뜬다 — 사슬을 여기
베껴 적어 두었기 때문에, 게임 쪽 공식만 고치고 이 검사기를 안 고치면 그 자리에서 잡힌다.

그 아래로 **다섯 가지 몸에 대한 실제 차감**과 붙는 상태이상, 그리고 **그 탄에 실제로 오는
놈**(`Run.kinds_for` — 전투와 같은 답이다)이 「몇 대에 죽는가」까지 붙어서 나온다.

### 「전투 중에 실제로 무슨 일이 있었나」

```bash
POCKER_NO_SAVE=1 ~/.local/bin/godot --headless --path . res://tests/dmg_check.tscn -- \
    --trace --wave 12 --team bell_shaman:2,ice_dagger:1 --max 80
```

## 3. 어떻게 게임 코드를 안 건드리고 다 보는가

**A-6 과 같은 수법이다** — `BattleSim` 을 물려받아 `_hurt()` 를 가로챈다. 다른 것은 두 가지뿐:

- 인게임 오버레이는 `game/dbg_sim.gd`(`class_name DbgSim`), 헤드리스 검사기는
  `tests/dmg_check.gd` 안의 **`class Tracer extends BattleSim`** 를 쓴다. 검사기 쪽은
  `Dbg.on` 을 안 보고 **언제나** 담는다 — 검사가 도는 동안은 늘 켜져 있는 셈이라서다.
- 검사기 쪽은 담은 것을 `rows` 배열에 그대로 쌓는다(상한 없음). 한 탄이면 수백 줄이라
  괜찮지만, 여러 탄을 잇달아 돌릴 거면 상한을 두어라 — 인게임 쪽이 `Dbg.CAP` 256 으로
  고리 버퍼를 쓰는 까닭이 그것이다.

★ **`game/battle_sim.gd` 에 `print` 를 박지 마라.** 박으면 (1) 자동 플레이 검사가 초당
수천 줄을 뱉어 몇 배로 느려지고 (2) 지우는 것을 잊으면 APK 에 그대로 실린다.

## 5. 함정

- **`POCKER_NO_SAVE=1` 을 반드시 붙여라.** 안 붙이면 이 검사가 만든 판이 「하다 만 판」으로
  남아서, 다음에 앱을 켠 사람이 그 판을 잇게 된다. 안 붙이면 검사기가 첫 줄에 경고한다.
- **`--trace` 는 씨앗을 고정해야 두 번 같은 판이 나온다** (`--seed`). 몬스터 편성은
  `Run.kinds_for(w)` 라 판 씨앗에만 매여 있지만, 치명타·마비·스폰 순서는 `BattleSim._rng` 다.
- **`dt` 를 바꾸면 결과가 조금 달라진다** — 쿨다운이 프레임 경계에 걸리는 자리가 달라서다.
  10% 안쪽이면 정상이고, 30% 넘게 벌어지면 **프레임에 매인 계산**이 생긴 것이다(`--selftest` 6번).
- **`sim.events` 는 화면이 매 프레임 비운다.** 검사기에서 돌릴 때 안 비우면 배열이 무한히
  자라 메모리를 먹는다 — `sim.step(dt)` 뒤에 `sim.events.clear()`.
- **`PackedFloat32Array` 로 hp 를 담지 마라.** hp 는 64비트다. 32비트로 깎아 담고 되돌리면
  `1e-6` 쯤이 남아서 **아무 일도 없던 몬스터가 매 걸음 「깎였다」로 잡힌다**
  (이 도구를 만들 때 실제로 22,000줄이 그렇게 나왔다).
- **`Run.heroes` 를 직접 만지는 것은 `tests/` 안에서만** 한다. 화면에서 그러면 겹친 수가
  딸려 오지 않는다(CLAUDE.md 14-3).
- **파스가 깨지면 출력 한 줄 없이 영원히 매달린다.** `_ready()` 가 안 불려 `quit()` 도 안
  불린다. 손으로 돌릴 때도 **언제나 `timeout` 과 `stdbuf -oL`**(CLAUDE.md 20).
- **`hit` 사건의 `n` 과 실제 차감은 다를 수 있다.** `n` 은 `dmg x em` 인데, 「거인 사냥」(x1.70)과
  「과잉 살상」(x1.90)은 **`_hurt` 안에서** 곱해지고 `em` 에도 `n` 에도 안 섞인다 — 최대 3.23배
  어긋난다. `--trace` 가 「요청」과 「실제 차감」을 **둘 다** 찍는 까닭이다.
- **`_hurt()` 는 `_crit` 인자를 안 쓴다**(밑줄 이름). 2차 피해(광역·연쇄·분열)에는 치명타가
  실려 있는데 사건에는 `crit: false` 로 나간다. 사건으로 치명타를 세면 적게 센다.
- **장판은 `aim`·`fire` 사건을 하나도 안 낸다.** `_heroes_fire` 에서 갈라져 `continue` 로
  `_aim()` 에 도달하지 않는다 — **발사 횟수를 세는 코드는 장판 영웅에 대해 언제나 0** 을 읽는다.
- **장판 틱은 정확히 0.25초가 아니다.** `if acc > 0.25` 초과 비교에 `acc = 0.0` 리셋이라
  실제 주기는 `ceil(0.25/dt) x dt` 다 — `dt=1/30` 이면 0.2667초, `dt=0.02` 면 0.26초.
- **`_hurt()` 가 범위 밖 `mi` 에 돌려주는 값은 `1.0`** 이다. **면역의 `0.0` 과 헷갈리지 마라.**
- **`_reap()` 이 진짜 `Run` 을 만진다** — `run.kills += 1` · `run.add_gold()` · `run.add_lives(-crush)`.
  프로브를 여러 번 돌릴 때는 **매번 판을 다시 세워라**. 그리고 목숨은 `_reap` 한 곳에서만
  깎는다 — 하네스가 또 깎으면 두 배가 된다(CLAUDE.md 14-2).
