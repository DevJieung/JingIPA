# 게임 흐름·규칙·안정성 업데이트

2026-09-08. 기존 로스터, 스프라이트 작업 및 미커밋 변경을 보존하며 게임 코드와 검증 도구를 개선했다.
스프라이트 품질 검수는 이번 범위에서 제외했다.

## 플레이에서 달라진 점

- 모든 주요 화면에 메뉴와 도움말을 추가했다. 전투 일시정지, 효과음 설정, 저장 후 타이틀 이동을 지원한다. Esc로 메뉴를 열고 닫고, 전투에서는 Space도 사용할 수 있다. 앱의 포커스를 잃으면 자동으로 멈춘다.
- 플레이 순서, 열 가지 족보, 실제 `Balance` 데이터를 쓰는 상성표를 게임 안에서 확인할 수 있다.
- 편성 화면에 현재 팀이 가장 불리한 적의 몸 속성과 직격 상성 배수를 표시한다. 광역의 대상 수, 화상, 둔화 등을 제외한 비교이며 승률 예측은 아니다.
- 결과 화면은 직접 누를 때까지 유지된다. 어두운 버튼의 글자 대비를 높였다.
- 화면 비율이 달라도 1280×800 기준의 전체 화면과 입력 좌표가 보존되도록 비율을 유지한다.

## 수정한 문제

| 문제 | 수정 |

| 첫 테마 소개에서 종료하면 복구할 수 없는 0탄 저장을 남김 | 첫 카드 배부 전에는 빈 체크포인트를 유지 |
| 완료 보상을 읽는 중 종료하면 같은 전투를 다시 시작함 | 보상과 상점 체크포인트를 함께 저장. 마지막 탄 승리도 즉시 기록 |
| 패배에도 클리어 보너스를 지급함 | 살아 있는 전투의 완료만 정산하고 중복 호출 차단 |
| 광선 x4가 단일 보스에게 한 발만 들어감 | 적들에게 나눠 쏜 뒤 남는 발도 배분하여 단일 대상 네 배 피해 보장 |
| 패시브 교체가 판매와 구매의 두 작업으로 분리됨 | 슬롯·진열·중복·골드를 먼저 검사하고 교체와 순액을 한 번에 확정 |
| 확정 후에도 코어 API로 리롤·추가 영웅 획득 가능 | DRAW 단계에서만 리롤과 최초 확정 허용 |
| 도감이 영웅 획득보다 먼저 파일에 저장됨 | 도감과 확정 결과를 같은 저장에 포함 |
| 저장 형식은 맞아도 카드 중복·배열 누락·테마 범위 오류가 복구됨 | 독립된 `RunValidation`에서 검사 후 현재 판을 변경 |
| 복구 실패가 현재 실행 상태를 일부 훼손함 | 검증을 먼저 마치고 복구 실패 시 현재 판 보존 |
| 실행 중 배열이 저장된 사전과 공유됨 | 저장 시 깊은 복사로 체크포인트 분리 |
| 저장 쓰기 실패를 무시하거나 파일을 덮어쓰다 손상 가능 | 임시 파일과 이전 정상 백업 사용, 오류 상태 및 재시도 지원 |
| 새 규칙 버전이 이전 평생 기록까지 무효화할 가능성 | 호환되지 않는 진행 중 판만 제외하고 기록·설정 보존 |
| 전투 재시작 시 공격 난수가 다시 바뀜 | 탄의 씨앗을 기본 전투 씨앗으로 사용 |
| 결과 화면에 이번 판 대신 평생 최고 족보 표시 | 이번 판의 최고 족보를 별도 집계·저장 |
| 비활성 버튼 뒤의 버튼이 눌림 | 최상위 영역이 비활성이어도 아래 입력 차단 |

## 코드와 파일 정리

- 저장 검사를 `core/run_validation.gd`, 공통 메뉴를 `game/menu_overlay.gd`로 분리했다. 정산은 `Run.settle_wave()`가 소유하며 화면이 직접 저장하지 않는다.
- 복구 전 검증으로 대체된 약한 카드 더미 검사와 재분배 경로, 의미 없는 테스트 분기를 제거했다.
- 피해 검사기의 삭제된 기본 캐릭터 ID를 현재 로스터로 교체했다. 기존 검사가 예외로 허용하던 광선 겹침 피해도 정상 배수로 검사한다.
- 로스터·효과음 검사에 `--check`를 추가해 검증 과정이 원본을 다시 생성하지 않도록 했다. 로스터 생성물의 불필요한 마지막 빈 줄도 제거했다.
- `build/.gdignore`, `docs/.gdignore`로 촬영물과 문서를 엔진 스캔에서 제외했다. `build/.gdignore`만 버전 관리하고 산출물은 계속 무시한다.
- 게임이 사용하지 않는 생성 임포트 메타데이터 **8,581개 / 8,266,501바이트**를 삭제했다. 이미지·영상·스프라이트 원본은 보존했다. 삭제 목록은 로컬 `build/upgrade/cleanup.json`에 있다.
- 검증기는 Godot 종료 코드와 엔진 오류를 함께 검사한다. 성공 문구가 있어도 엔진 오류가 있으면 실패한다. APK도 새 임시 산출물이 성공했을 때만 최종 파일을 교체한다.

## 검증 결과

- `tools/verify.sh --skip-sprites`: 통과. 임포트, 부팅, 표 일치, 저장·게임 흐름, 실제 피해, 족보, 화면 순환, 밸런스, 폰트, Android APK 빌드를 포함한다.
- 추가 흐름 회귀 검사 **101건 통과**. 손상 저장 거절과 무변경 보장, 백업 복구, 쓰기 실패 후 재시도, 교체 원자성, 실제 메뉴 입력, 일시정지와 재개, 보상 중복 방어, 전투 재시작 재현성을 검사한다.
- 족보 **2,598,960가지 전수 검사 통과**.
- 단일 대상에게 모든 공격 방식의 **4겹 피해가 4배**인지 실제 시뮬레이션으로 확인했다.
- 자동 플레이 12판: 변경 전·후 모두 **4판 클리어, 중간 97탄, 최저 89탄, 최고 100탄**. 1~6탄 크리스탈 손실 0. 다섯 속성의 사용률 모두 10% 이상. 소규모 정책 표본이며 사람의 실제 클리어율을 뜻하지 않는다.
- 최종 변경 후 표 검사, 실제 화면 순환, 1600×900 요청 화면의 101건 흐름 검사를 별도로 통과했다.
- 1280×800 화면 7종과 와이드 화면 메뉴·족보를 실제 렌더링으로 확인했다. 와이드 요청에서는 1440×900 게임 영역을 유지한다.
- 검증기에 가짜 엔진 오류와 비정상 종료를 각각 주입하여 성공 문구가 있어도 모두 실패하는지 확인했다.
- APK에 새 메뉴·검증 코드가 포함되고 `tests/`, `tools/`, `docs/`, `build/`는 제외되는 것을 확인했다.

로컬 산출물: `~/pokerdefense-test.apk` (91,437,552바이트), `build/upgrade/verify.log`, `build/upgrade/flow-final.log`, `build/upgrade/shots/`, `build/upgrade/wide/`.

## 출시 전에 남은 확인

이번 결과는 핵심 플레이와 안정성의 개선 및 테스트 APK다. 상용 출시 완료를 의미하지 않는다.
실제 안드로이드 기기의 장시간 100탄 플레이, 발열·메모리·프레임 유지, 홈/복귀·강제 종료와 저장 복구,
작은 화면의 터치 조작을 추가 확인해야 한다. 별도 진행 중인 스프라이트 검수와 실제 플레이어 대상 난이도·학습성 평가도 남아 있다.
스토어용 서명·배포는 수행하지 않았다.
