# 설계 문서 — 왜 이렇게 만들었는가

이 문서는 "무엇이 어디 있는지"보다 **"왜 이 선택을 했는지"** 를 남깁니다.
나중에 고칠 때 무심코 되돌리면 안 되는 결정들이 여기 있습니다.

---

## 1. 학습 루프

```
문제 제시 (숫자와 기호만, 한글 0어절)
   ↓  아이가 4지선다 중 하나 탭
★ 블록 시연 ★  ← 여기가 이 게임의 존재 이유
   ↓
정답 → 개구리가 혀로 공격 → 뱀 처치 → 다음 문제
오답 → 뱀이 막아냄 → 같은 문제 다시 (블록은 화면에 남는다)
```

### 왜 보상이 시연 뒤에 오는가

탭하자마자 개구리가 공격하면, 아이의 뇌는 **보상을 '탭'에 연합**합니다.
그러면 블록 시연은 "빨리 넘기고 싶은 방해물"이 됩니다.
보상은 반드시 수학적 설명 **뒤에** 와야 시연이 보상의 일부가 됩니다.

### 오답 사다리 (벌이 아니라 계단)

**목숨(하트)이 없다.** 시도 횟수 제한도, 게임 오버도 없다. 이것을 되돌리지 말 것 —
아이가 마음 놓고 여러 번 눌러볼 수 있어야 "위치 찍기"가 아니라 "계산 다시 하기"를 한다.

| 시도 | 시연 | 그 밖에 |
|---|---|---|
| 1차 오답 | 과정 전부 + 마지막 수는 `?` | 뱀이 막아내는 중립 연출. 블록을 세면 답이 나온다 |
| 2차 오답 | 과정 전부 + `?` (숙달 단축 해제, 천천히) | 이 문제를 복습 큐에 넣음 (3문제 뒤 재출제) |
| 3차 오답 | **답까지 전부** | 정답 보기가 반짝임 → 눌러보게 함. **보상은 정답과 동일**. 이후 3문항 난이도 완화 |

- 오답 보기를 **제거하지 않습니다.** 제거하면 "찍기"를 학습시킵니다.
- 보기 배치를 **바꾸지 않습니다.** 문제 키로 시드를 고정해서, 재도전할 때
  "위치를 다시 찾기"가 아니라 "계산을 다시 하기"를 하게 만듭니다.

### 절대 넣지 말아야 할 것: 타이머

시간제한은 이 연령대 수학 불안의 주된 시작점이고, 압박은 수학 사실을 꺼내는 작업기억을 막습니다.
카운트다운, 줄어드는 체력바, "빨리!" 연출 — 전부 금지입니다.
긴장이 필요하면 뱀이 아주 천천히 다가오되 **절대 도달하지 않는** 앰비언트로 처리하세요.

## 2. 블록 시연 (`src/game/block_stage.gd`)

```
┌────────────────────────────────────┐
│   ■■■       +       ■■             │ ← 항별 무리. 문제의 숫자와 1:1 대응
│    3                 2             │
├────────────────────────────────────┤
│  십 │ ┌─┬─┬─┬─┬─┐                  │ ← 합치는 판 (자릿값 판 + 십틀)
│  ▮  │ ├─┼─┼─┼─┼─┤                  │
└────────────────────────────────────┘
                5                      ← 세는 중인 수
```

### 문제와 설명은 같은 식이어야 한다

- **연산 기호의 x 를 맞춘다.** `ProblemCard.op_centers()` 가 카드 안 '+' 의 x 를 알려주고,
  `BlockStage.set_op_anchors()` 가 설명의 '+' 를 정확히 같은 x 에 놓는다
  (카드와 무대는 배틀 화면에서 x/폭을 똑같이 잡으므로 좌표가 그대로 통한다).
  블록이 커서 왼쪽 무리가 화면 밖으로 밀릴 것 같으면 **블록 크기를 줄여서** 정렬을 지킨다.
- **무리마다 격자를 미리 깔아 둔다.** 항상 5칸 폭이라 `6 = 5칸 한 줄 + 1` 처럼 한눈에 읽히고,
  왼쪽 무리와 오른쪽 무리의 폭이 같아져 둘이 분명히 구분된다.
  격자 모양은 합치는 판의 십틀과 같게 해서 "이 칸들이 저 판으로 옮겨간다"가 자연스럽게 읽힌다.
- 숫자 라벨은 격자 아래로 `1.15U` 내려 블록과 붙지 않게 한다.

### 순서가 곧 설명이다 (이 순서를 바꾸지 말 것)

0. **격자와 연산 기호가 처음부터 깔려 있다** — 답을 고르기 전에도 아래 그림이
   위의 식과 같은 모양이다 (`[격자] + [격자]` / 아래 합산판). 예전에는 기호가 시연 도중에
   나타나서, 답을 고르는 시점에는 빈 격자 둘만 있고 그 사이가 비어 있었다.
1. 문제 카드의 **왼쪽 숫자가 커지며 강조**된다 (`term_focus` 시그널 → `ProblemCard.highlight_term`)
2. 왼쪽 무리에 블록이 **하나씩** 놓인다 — 같이 셀 수 있어야 하므로 한꺼번에 나오면 안 된다
3. 오른쪽 숫자가 강조되고 오른쪽 무리에 블록이 하나씩 놓인다
4. 왼쪽 무리를 **합치는 판에 쏟는다** → 이어서 오른쪽 무리를 쏟는다
5. 결과를 센다

전체 속도는 `BlockStage.PACE` 하나로 조절한다 (크면 느리다).

**블록 하나를 놓고 다음 것까지 쉬는 간격(`FILL_GAP`/`POUR_GAP`)은 개수와 무관하게 고정이다.**
예전에는 "전체 0.8초를 개수로 나눠" 써서 3개짜리 탄과 15개짜리 탄의 손놀림이 세 배 가까이 달랐다.
아이는 그 차이를 "블록이 많구나"가 아니라 "이 탄은 빠르다"로 읽는다.
오래 걸리는 건 개수가 많아서지 속도 때문이 아니어야 한다.

### 받아올림은 십틀의 모양으로 보인다 (묶는 연출은 넣지 않는다)

`_pour_group()` 은 낱개를 **반드시 한 개씩** 옮깁니다. 한꺼번에 날아가면
세기 오류(답 ±1)를 아이가 스스로 고칠 기회가 사라지고, 10이 채워지는 순간도 안 보입니다.
합산판은 5칸씩 두 줄인 **십틀 두 개**라서, 앞 틀이 꽉 차고 뒤 틀로 넘어가는 것 자체가
받아올림의 그림입니다. 9탄의 `7 + 5` 는 특별 처리 없이 교과서 지도 방식대로 보입니다:
파란 블록 3개가 먼저 들어가 앞 틀을 채움 → 남은 2개가 뒤 틀로 → 12.

**★10이 차는 순간 금색 테두리로 묶고 "10" 배지를 붙이는 연출은 제거했습니다.**
설명 자체는 옳았지만 전용 효과음 + 정지 비트까지 합쳐 한 문제마다 2초 가까이 늘어났고,
아이가 **기다리는 시간이 계산하는 시간보다 길어졌습니다.**
되살리지 마세요 — `tests` 의 `[4]` 가 `bundle` / `borrow` 장면이 다시 생기면 실패시킵니다.

### 뺄셈은 '박치기' 로 보여준다

덧셈과 **완전히 같은 흐름**으로 시작한다 — 왼쪽 격자, 기호, 오른쪽 격자.
다른 점은 마지막 단계뿐이다:

- 덧셈: 두 격자를 합산판에 **쏟는다**.
- 뺄셈: 왼쪽 격자만 쏟고, 오른쪽의 **붉은 블록이 하나씩 날아가 판의 블록에 부딪혀
  둘 다 사라진다** (`_collide_remove`).

이렇게 하면 "빼는 수"가 화면에 실체로 존재하고, 1:1 로 없어지는 게 보인다.
예전처럼 숫자 라벨만 띄우고 판에서 블록이 그냥 사라지면 "무엇이 몇 개 없어졌는지" 가 흐릿하다.

빼는 블록을 놓을 때는 소리도 다르다 — 얹을 블록은 둥근 마림바 톡(`block_pop`),
**빼는 붉은 블록은 딱딱한 "챡!"(`block_snap`)**. 화면을 안 봐도 "이건 덜어낼 것"이 귀로 갈린다.

**없애는 순서는 뒤에서부터다.** 빨간 격자에 마지막으로 놓인 블록이 먼저 날아가고,
판에서도 마지막 칸이 먼저 없어진다. 앞에서부터 빼면 남은 빨간 블록 사이에 구멍이 생겨
(3개 중 첫 칸이 비고 2·3번 칸만 남는다) "몇 개 남았지?" 를 세려면 흩어진 걸 다시 읽어야 하고,
격자는 왼쪽부터 / 판은 오른쪽부터 줄어서 두 방향이 어긋난다.
뒤에서부터 빼면 남은 것이 늘 앞쪽에 붙어 있어 3 → 2 → 1 이 그대로 보인다.
(테스트 `[4c]` 가 "살아있는 블록은 늘 앞쪽 연속 구간" 을 지킨다.)

받아내림도 같은 이유로 별도 장면을 두지 않습니다. 판의 블록은 늘 낱개라
`12 − 3` 은 뒤 틀의 2개가 먼저 없어지고 앞 틀에서 1개가 더 없어지는 것으로 그대로 보입니다.
이 그림이 `smaller_from_larger` 버그(자리마다 큰 수에서 작은 수를 빼는 것)를 반박합니다.

### 빈칸 문제(`a + □ = b`)는 격자를 셋 다 깐다

`a` 격자, `□` 격자, 합산판 — 식에 적힌 것이 화면에도 그대로 있어야 같은 그림으로 읽힙니다.
`□` 자리 격자는 보기 버튼과 같은 초록이고 아래에 `?` 가 적혀 있어
"여기가 내가 채울 곳" 이 먼저 읽힙니다 (`_staging_spec()` 의 `blank` 플래그).

답을 고르면 `_fill_blank_coupled()` 이 **하나의 트윈 안에서** 두 가지를 동시에 합니다:
`□` 격자에 블록 하나가 놓이고, 같은 순간에 합산판이 한 칸 늘어납니다
(`a − □ = b` 형태라면 한 칸 줄어듭니다).
**따로 움직이면 안 됩니다** — 아이가 그걸 '다음 단계' 로 읽지 '같은 사건' 으로 읽지 않습니다.
이 대응 관계가 이 문제 유형이 가르치는 전부입니다.

### 뱀은 월드마다 다르고, 뒤로 갈수록 세 보인다

`Snake.WORLD_LOOK` 한 표에서 색·몸통 굵기·뿔 개수·등가시 개수·눈썹 각도가 함께 올라갑니다.
1월드는 통통한 초록 늪뱀, 6월드는 검붉고 뿔과 등가시가 난 뱀왕의 부하입니다.
왕(보스)은 **같은 종족의 더 크고 진한 개체**입니다 — 색상을 바꾸지 않고 명도만 낮추고
왕관과 덩치로 구분합니다. 색까지 바꾸면 "이 월드의 우두머리"로 안 읽힙니다.

**진짜 공포 요소는 넣지 않습니다** — 피, 사실적인 송곳니, 붉게 빛나는 눈, 해골.
'세 보이는 것'은 실루엣(뿔·가시·굵기)과 색으로만 만들고 눈은 끝까지 크고 동그랗게 둡니다.
7살이 밤에 무서워서 게임을 못 켜면 아무 소용이 없습니다.
(생성 그림 `snake_w1~6` / `boss_w1~6`, 없으면 코드 드로잉이 같은 규칙으로 대체합니다.)

### 색 규칙

합쳐진 뒤에도 **원래 색을 유지합니다.** 회색으로 통일하면 "7과 5가 합쳐져 12"라는 관계가 증발합니다.
합산판의 10칸도 각 칸이 출신 색을 유지합니다 —
`7 + 5` 로 만들어진 10은 주황 7칸 + 파랑 3칸입니다.

### 곱셈은 자릿값 판을 쓰지 않는다

가르칠 대상이 **직사각형성**입니다. `4 × 7 = 28` 을 십 막대 2개 + 낱개 8개로 먼저 보여주면
배열 구조가 깨집니다. 배열을 완성해 보여준 다음에만 (선택적으로) 십 막대로 재편성합니다.

**표기 방향 — 반드시 지킬 것**: 한국 교과서는 `a × b` 를 **"a씩 b묶음 = a의 b배"** 로 읽습니다.
`a` = 한 묶음의 크기, `b` = 묶음의 수. 따라서 `3 × 4` 는 **3개짜리 묶음 4개**이고,
화면에서는 **b행 × a열**(한 줄이 한 묶음)로 그립니다.
영어권 자료의 "a groups of b" 관례를 그대로 옮기면 아이 교과서와 정반대가 됩니다.

### 장면 분할과 건너뛰기

시연은 3~5개 장면(`segment`)으로 나뉘고 사이에 0.3초 정지가 있습니다. 전체 2~4초.
화면을 탭하면 **현재 장면의 끝으로 점프**합니다 — 전체를 빨리 감으면 아이가 무슨 일이 일어났는지 못 알아봅니다.

**숙달 단축**: 같은 탄에서 첫 시도 정답이 3연속이면 시연이 자동으로 짧아집니다(`set_flash_mode`).
틀리는 순간 즉시 풀버전으로 돌아옵니다. "몇 초면 지루해지나"의 답은 고정 상수가 아니라 숙달도의 함수입니다.

**다시 보기 버튼은 두지 않습니다.** 매 문제 화면에 새로고침 아이콘이 떠 있으면 시선을 뺏고
아이가 "뭘 눌러야 하지?"를 하나 더 고민하게 됩니다. 틀리면 어차피 시연이 자동으로 다시 재생됩니다.

### 결과를 다시 세지 않는다

블록을 판에 쏟는 동안 숫자가 이미 하나씩 올라갑니다(`_pour_group` 안의 `_set_count`).
그런 다음 처음부터 또 세면 **"방금 센 걸 왜 또 세지?"** 가 되어 오히려 헷갈립니다.
그래서 `_count_result()` 는 다시 세지 않고 **결과 숫자만 한 번 크게 강조**하고,
판 위의 블록·막대가 한꺼번에 한 번 반짝여 "이게 다 해서 이 수"라는 것만 보여줍니다.

## 3. 문제와 오답 (`src/core/problem_gen.gd`)

오답은 무작위 숫자가 아니라 **오류 모델**에서 나옵니다. 각 후보에는 태그가 붙습니다.

| 문제 | 오답 | 태그 | 무슨 뜻인가 |
|---|---|---|---|
| 7 + 5 = 12 | **2** | `carry_dropped` | 받아올림을 버림 |
| 12 − 3 = 9 | **1** | `smaller_from_larger` | 자리마다 큰 수 − 작은 수 (Brown & Burton 1978) |
| 14 − 9 = 5 | **1** | `ten_only` | 10에서만 빼고 낱개를 잊음 |
| 7 × 8 = 56 | **49 / 63** | `operand_error_*` | 같은 단의 이웃 곱 (아동 곱셈 오답의 약 3/4) |
| 3 × 4 = 12 | **7** | `mul_as_add` | 곱셈을 덧셈으로 |

> **자릿수를 정답과 맞추지 마세요.** `7+5 → 2` 는 한 자리이고 정답은 두 자리인데,
> 그 불일치가 바로 그 오답의 진단 가치입니다. "보기는 모두 두 자리" 같은 미화 규칙을 넣으면
> 가장 좋은 오답이 사라집니다.

아이가 고른 오답의 태그는 `Game.error_tags` 에 누적되어 **부모 화면**에 한국어 설명으로 나옵니다.

**보기 배치 규칙**
- 시드는 문제 키(`Problem.key()`)로 고정 → 같은 문제는 항상 같은 배치.
- 정답이 3번 연속 같은 자리에 오면 한 칸 회전 (`Battle._apply_slot_rule`).
  7~8세는 "항상 두 번째" 같은 위치 전략을 아주 빨리 만듭니다.
- 오름차순 정렬 금지 — "가장 큰 수가 답" 같은 비수학적 전략을 학습시킵니다.

## 4. 커리큘럼 (`src/core/curriculum.gd`)

2022 개정 교육과정 초1~2 '수와 연산'의 실제 지도 순서 그대로 18탄. 근거는 [README](../README.md#진행-구조)의 표.

**절대 순서를 바꾸면 안 되는 지점**

- **4탄(10 모으기·가르기)** 은 9탄(받아올림)과 10탄(받아내림)의 **유일한 전제조건**입니다.
- **8탄(10을 만들어 더하기)** 은 9탄의 정확한 리허설입니다.
  `7+5` 는 내부적으로 `7+3+2` 인데, 8탄에서는 이미 쪼개진 상태로 주어지므로
  "쪼개기" 부담 없이 "10을 채우고 나머지를 얹는다"만 익힙니다. 이 탄을 건너뛰면 9탄 실패율이 급증합니다.
- **곱셈구구 순서 2·5 → 3·6 → 4·8 → 7·9 → 1** 은 교과서 순서입니다.
  2·5단이 먼저인 이유는 뛰어세기가 이미 익숙하고 곱의 일의 자리가 주기적이라 패턴이 눈에 보이기 때문입니다.
  6단은 3단의 두 배, 8단은 4단의 두 배라 짝으로 묶여 있습니다.

**4탄의 `a + □ = 10` 형태**: `a + (10−a) = ?` 는 답이 항상 10이라 찍으면 100% 맞습니다. 절대 쓰지 않습니다.

## 6. 기술 결정

### 렌더러: `gl_compatibility` (양쪽 플랫폼 모두)

`mobile` 렌더러를 쓰면 Godot이 iOS Info.plist에 `iphone-ipad-minimum-performance-a12` 를
**강제로** 주입해서 iPhone 8 / X 이하(2018년 이전) 기기가 전부 설치 불가가 됩니다.
아이에게 물려주는 기기는 대개 구형이라, 호환성을 택했습니다.

대가로 MSAA를 못 씁니다 (`gl_compatibility` 에서 동작하지 않음).
그런데 `draw_polygon()` / `draw_colored_polygon()` 에는 `antialiased` 인자가 **없습니다**.

→ **그래서 채워진 도형은 전부 `DrawUtil.fill_aa()` 로 그립니다.**
폴리곤을 채운 뒤 같은 색의 안티에일리어싱된 외곽선을 덧그려 가장자리를 부드럽게 만듭니다.
`draw_colored_polygon()` 을 직접 부르면 계단 현상이 그대로 보입니다. **이 규칙을 어기지 마세요.**

MSAA를 쓰고 싶고 A12 미만 기기를 포기해도 된다면 `project.godot` 에서:
```
rendering/renderer/rendering_method.mobile="mobile"
rendering/anti_aliasing/quality/msaa_2d=2
```

### 이미지 에셋 0개

개구리·뱀·배경·블록·버튼 전부 `_draw()` 로 그립니다. 사운드도 파이썬으로 합성합니다.
덕분에 어떤 해상도에서도 선명하고, 앱이 매우 가볍고, 저작권 문제가 없습니다.
다시 만들려면 `tools/gen_audio.py`, `tools/gen_icons.py`.

### 씬 파일은 루트 노드 하나뿐

모든 UI는 코드로 만듭니다. `.tscn` 은 루트 노드 + 스크립트만 담습니다.
손으로 쓴 씬 파일의 구조 오류 가능성을 없애고, 레이아웃을 전부 한 곳(`_layout()`)에서 보게 하려는 것입니다.

### Godot 4.7 관련 함정

- **엔진 기본 폰트에는 한글 글리프가 없습니다.** `ThemeDB.fallback_font` 는 Open Sans 라
  모든 한글이 두부(□)로 나옵니다. `gui/theme/custom_font` 로 Jua를 지정해야 합니다.
  `get_string_size()` 는 그럴듯한 값을 돌려줘서 **오류로 드러나지 않고 화면에서만 깨집니다.**
- **Jua 폰트에 `×`, `−`, `÷` 글리프가 없습니다.** 그래서 연산 기호는 `Glyphs` 로 직접 그립니다
  (블록 컨셉과도 더 잘 맞습니다).
- **JSON은 모든 정수를 float으로 돌려줍니다.** 저장 파일을 읽을 때 반드시 `int()` 로 다시 조입니다.
- **`draw_string()` 의 `pos` 는 베이스라인 좌하단**입니다(좌상단이 아님). `Fonts.draw_centered()` 를 쓰세요.
- **`*.uid` 파일을 gitignore 하지 마세요.** Godot 4.4+ 가 리소스 참조에 씁니다.
- **`Tween.kill()` 은 `finished` 를 내지 않습니다.** `await tw.finished` 를 걸어둔 코루틴이 영원히 멈춥니다.
  건너뛰기는 `kill()` 이 아니라 `set_speed_scale(60.0)` 으로 구현했습니다.
- **트위너가 하나도 없는 Tween** 은 `finished` 를 내지 않고 엔진 오류만 찍습니다.
  `BlockStage._run()` 이 `has_tweeners()` (4.7 신규)로 걸러냅니다.
- **GDScript 람다는 지역 변수를 값으로 캡처합니다.** 콜백에서 바깥 지역 변수에 쓰려면
  배열/객체로 감싸야 합니다. (테스트 코드에서 한 번 물렸습니다.)
- **`handheld/orientation` 은 정수입니다** (Godot 3의 `"portrait"` 문자열이 아님).
  `0`=가로 `1`=세로 `2`=역가로 `3`=역세로 `4`=센서가로 `5`=센서세로 `6`=센서.
  이 게임은 `4`(센서 가로)라 태블릿을 어느 쪽으로 돌려 들어도 가로로 섭니다.
- **`stretch/aspect="expand"` 에서 뷰포트는 기준 해상도보다 작아지지 않습니다.**
  `viewport = window / min(win.x/base.x, win.y/base.y)` 이므로 두 축 모두 항상 base 이상이고
  한쪽만 늘어납니다. 기준이 1280×800 이므로 **가로 배치의 최악 조건이 정확히 1280×800** 입니다 —
  여기서 답 버튼 200px 이 들어가면 다른 어떤 가로 기기에서도 들어갑니다.
- **`import_etc2_astc=true` 가 없으면 안드로이드 익스포트가 아예 막힙니다.**

## 7. 저장 데이터

`user://save.json` 하나. 계정도, 서버도, 통신도 없습니다.
쓰기 전에 직전 내용을 `save.bak.json` 으로 굴려두어 앱이 중간에 죽어도 하나는 남습니다.
모바일에서 홈 버튼을 누르는 순간(`NOTIFICATION_APPLICATION_PAUSED`) 즉시 저장합니다.

```jsonc
{
  "version": 2,
  "settings": { "sfx": true, "bgm": true, "fast_animation": false,
                "reduce_motion": false, "session_limit": 20 },
  "stars":  { "0": 3, "1": 2 },            // 탄 인덱스 -> 별 1~3
  "stats":  { "0,0,-1,0,7-5": [4, 1] },    // 문제 키 -> [맞음, 틀림]
  "error_tags": { "carry_dropped": 3 },    // 오류 유형 누적 (부모 리포트)
  "totals": { "correct": 0, "wrong": 0, "tiers_cleared": 0, "snakes": 0, "seconds": 0.0 },
  "endless_best": 0,
  "last_tier": 0
}
```

`stats` 는 900개를 넘으면 "틀린 적 없는 것"부터 정리합니다 (복습 가치가 낮으므로).
