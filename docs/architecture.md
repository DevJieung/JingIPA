# 공룡섬 — 왜 이렇게 만들었나

게임별 설계 근거는 [`dino-rules.md`](dino-rules.md) · [`frog-rules.md`](frog-rules.md) ·
[`frog-architecture.md`](frog-architecture.md) 에 그대로 남아 있다. 이 문서는 **합치면서
새로 정한 것**과 **그 근거**만 적는다.

---

## 1. 왜 합쳤나

두 게임 다 잘 돌아가는데 아이가 몇 판 하면 지루해했다. 코드를 재어 보니 원인이 서로 달랐다.

**공룡 찾기는 18탄에서 난이도가 수식상 완전히 정지했다.**

```
dino_count(s) = clamp(2 + s/5, 2, 5)   → 15탄부터 영원히 5마리
n_props       = clamp(3 + s/9, 3, 5)   → 18탄부터 영원히 5개
가림 정도                               → 탄과 무관하게 53~56% 고정
```

각 탄 100방씩 생성기를 재현해 돌린 실측에서 20/30/50/100/200탄은 통계적으로 동일한
방이었다. **47탄과 16탄은 화면상 같은 방이다.**

**개구리 용사는 반대로 기다림이 문제였다.** 10탄 20문제 세션이 10.1분인데 그중 88%가
화면을 보기만 하는 시간이고, **아는 문제에도 같은 시연이 매번 나왔다** — 숙련이 처벌됐다.

그리고 둘 다 **앱을 다시 켤 이유**가 없었다. 공룡 50종 데이터는 다 있는데
저장에는 정수 두 개(`best_stage`, `found`)뿐이라 **50종을 다 봤는지 게임도 아이도 몰랐다.**

→ 합치는 목적은 "게임 모음집"이 아니라 **두 게임이 하나의 진행을 공유하게 만드는 것**이다.

## 2. 세계관은 지어내지 않았다

- 공룡 찾기의 수작업 6방은 전부 집안(거실·부엌·침실·욕실·놀이방·다락방)이고,
  자동 생성 26테마 안에 이미 **우주방·바다방·숲속방**이 섞여 있다
  (`games/dino/scripts/room_gen.gd` 의 `THEMES`) — 생성기가 이미 "집인데 방마다 딴 세상"이라고 말한다.
- 개구리 용사의 6월드는 전부 집 밖 자연(개굴 늪지·연꽃 호수·버섯 숲·안개 동굴·곱셈 신전·뱀왕의 성).
  **안/밖이 이미 그어져 있었다.**
- 공룡 키는 116~184px 로 소파(190~230px)보다 작다. **작은 공룡이 사람 집에 산다**는
  설정이 이미 그림에 있다.

### 양방향 인과 — 이것이 "모음집"과 갈리는 지점

| 방향 | 무엇이 건너가는가 | 어떤 구멍을 메우는가 |
|---|---|---|
| 수학 → 공룡 | 층을 열면 그 층 전용 방 테마·가구가 는다 | 공룡 찾기가 정지하던 자리 |
| 공룡 → 수학 | 도감에서 고른 공룡이 개구리 옆에 선다 | 개구리 화면이 18탄 내내 고정이던 것 |
| 양쪽 → 알 | 알의 금은 공룡 8마리 **또는** 문제 8개로 깨진다 | 두 게임이 공유하는 유일한 진행 막대 |

**절대 넘지 않는 선**: 층 해금은 **재료의 추가이지 문 잠금이 아니다.** 수학을 한 번도
안 해도 공룡 찾기는 영원히 할 수 있어야 한다. 이 선을 넘으면 "수학을 해야 공룡을 볼 수
있다"로 읽혀 앱 자체를 피하게 되고, 그러면 안 합친 것만 못하다.
같은 이유로 **알로만 얻는 종을 만들지 않는다** — 그러면 수학을 못 하는 동생에게
도감의 일부가 영구히 검은 실루엣이 된다.

## 3. 셸은 게임을 모른다

```
Shell        저장 파일 · 기기 설정 · 프로필 · 공용 도감 · 뷰포트 프로파일 · 세션
Router       화면 전환. 페이드가 덮은 순간 Shell.enter_game() 을 부른다
GameRegistry ★ 게임이 등록되는 유일한 곳 (배열 한 줄 + 씬 하나)
Hub          둥지방
```

대안은 `Router` 안에 `goto_dino()` 를 메서드로 박고 뷰포트 표를 상수로 두는 것이었다.
그러면 게임 #3 을 넣을 때 Router 를 고치고, #4 에 또 고친다. **셸이 게임을 알게 되면
게임이 늘어날수록 셸이 부서진다.**

`Router` 에 아직 개구리 전용 멤버(`pending_tier`, `goto_battle`, `goto_endless`)가 남아
있다 — 게임 #3 이 올 때 `games/frog/frog_route.gd` 로 내리고 `goto_hub`/`goto_game`/
`goto_scene` 만 남긴다. **갚아야 할 빚으로 적어 둔다.**

## 4. 폰트를 통일하지 않는다 (실측)

`gui/theme/custom_font` 는 프로젝트 전역 단일 키인데 게임마다 폰트가 다르다.
그런데 **싸울 필요가 없었다.**

| 대상 | 어떻게 폰트를 얻나 | 수정 |
|---|---|---|
| 프로젝트 fallback | `core/fonts/DinoKR.ttf` — 한글 11,172/11,172 (100%) | — |
| 공룡 찾기 | Label/Button 이 fallback 을 그대로 받음. 폰트 오버라이드 0건 | **0줄** |
| 허브·셸 | fallback → DinoKR (허브 문구는 한글 100% 커버가 필요) | — |
| 개구리 용사 | `Fonts.MAIN` 으로 Jua 를 직접 preload 해 `draw_string` 에 넘김 | **1줄** |

**통일이 불가능한 이유:**
- Jua 로 통일 → 공룡 찾기는 방 이름 26종·공룡 50종을 코드에서 만들어 쓰는데
  Jua 의 한글 커버리지가 **21.2%** 다. 새 낱말마다 룰렛이 된다 (`·` 조차 없다).
- DinoKR 로 통일 → `Fonts.draw_centered()` 가 `(ascent−descent)*0.5` 로 세로 중심을
  잡는데 두 폰트의 값이 달라 **모든 중앙정렬 글자가 폰트 크기의 13.6% 만큼 아래로 밀린다**
  (108pt 면 약 15px). 격자·연산기호·등호 정렬 규칙이 통째로 어긋난다.

**⚠ Theme 는 CanvasLayer 경계를 넘지 못한다** (재현 확인). 공룡 찾기의 HUD·타이틀·배너·카드는
`ui: CanvasLayer` 의 **직속 자식**이라 우연히 동작하는 구조다. 사이에 CanvasLayer 를 한 겹
더 끼우면 조용히 fallback 으로 돌아간다.

**⚠ 두 `.import` 다 `allow_system_fallback=true`** 라 실기기에서는 OS 폰트가 빠진 글리프를
메워 준다 — **눈으로는 절대 안 잡힌다.** `tools/check_font.py` 를 반드시 돌릴 것.
그 검사기는 **검사 대상이 0개면 실패**한다 (경로가 바뀌면 조용히 초록불을 내던 문제).

## 5. 뷰포트도 통일하지 않는다 (실측)

기본 **1280x800 / expand**, 공룡 찾기 진입 시에만 런타임으로 **1280x720 / keep** 전환.
`Router` 의 페이드가 화면을 완전히 덮은 순간에 바꾸므로 아이 눈에는 안 보인다.
**양쪽 배치 코드 0줄.**

- **720/keep 으로 통일하면** 노치 있는 아이폰에서 개구리 답 버튼이 24px 화면 밖으로 나간다.
  답 버튼 200px 과 간격 36 은 절대 못 줄인다. (800 − 720 = 80px 이 정확히 노치 여유분)
- **800/expand 로 통일하면** 공룡 찾기의 소품 y 좌표 42개 · 바닥선 `FY=470` · 클램프 ·
  가림 경계 118 이 전부 720 에 손으로 맞춰져 있어 통째로 다시 맞춰야 한다.

→ 개구리 테스트 [7]의 `sizes` 배열에 `Vector2(1280,720)` 를 **추가하지 마라.**

**SubViewport 를 쓰지 않은 이유**: 좌표계에 한 단계가 더 껴서 `get_global_mouse_position()`
과 `tools/dino/recorder.gd` 의 Transform2D 누적 규약을 다시 검증해야 한다.
런타임 전환은 그게 없다 (`/root/DinoFind` 의 global_transform 이 항등임을 확인).

## 6. 난이도 — 축을 하나에서 여럿으로

**올리는 축은 셋뿐이다.** 볼 것이 늘거나(A) · 잘 안 보이거나(B) · 고를 것이 는다(C).
기다림(E)은 **내려가기만** 하고, 평가(F)와 시간 압박(G)은 절대 올리지 않는다.

```
E = clamp(stage + skill, 1, 999)     # skill ∈ [-8, +10], 저장됨, 화면에 절대 안 나옴
```

탄 번호는 아이가 보는 숫자, `E` 는 축이 읽는 숫자다.

### 열쇠는 파고듦(`u`) 파라미터

예전에는 자리가 "가구당 좌/우/뒤"로 **이산**이라 가림%가 뽑고 보니 나온 값이었다.
그래서 목표값을 줘도 3%p 밖에 안 움직였다. `spot_transform` 에 `u` 를 넣어 연속으로
만들고 목표 가림%에 이분탐색(12회)으로 맞추면 **가림%가 진짜 손잡이가 된다.**

`u` 가 없는 spot(손으로 꾸민 1~6탄)은 `0.0` 이라 **픽셀 단위로 예전과 같다.**

### 실측 (각 E당 100방, 총 1,800방 / 공룡 8,100마리)

| E | 공룡 | 가구 | 목표 밴드 | 실제 가림 | 마릿수부족 |
|---|---|---|---|---|---|
| 1 | 3 | 3 | 30~58 | 44.9% | 0 |
| 10 | 5 | 4 | 33~62 | 49.8% | 0 |
| 20 | 6 | 5 | 41~72 | 58.9% | 0 |
| 30 | 6 | 6 | 49~80 | 63.8% | 0 |
| 100 | 6 | 6 | 50~80 | 64.2% | 0 |

가림 평균이 **44 → 64% 로 단조 상승**한다(현행은 전 구간 53~56% 평평).
미취학 프로필은 천장이 낮아 **40 → 54%** 에서 멈춘다.

### 순서가 중요하다 — 실측으로 뒤집힌 것

초안은 "가구를 늘려 여유를 만든 뒤 가림%를 손잡이로 쓴다"였는데 **반대였다.**
가구를 촘촘히 밀어 넣으면 공룡이 가구 두 개에 걸쳐 가림률이 상한을 넘고 **그 자리가
통째로 탈락한다** — 배치 수는 4.12→4.93 으로 오르는데 **쓸 수 있는 자리는 5.88→4.95 로 준다.**
→ `solve_u` 를 가구 상한 인상보다 **먼저** 넣어야 한다.

### 적응형 — 신호로 시간을 재지 않는다

- **공룡 찾기**: 힌트 발동 횟수만. 내림 1방 만에, 오름 2방 연속, 중간은 데드존.
- **개구리 용사**: 누적 첫시도 정답 횟수만.

초시계를 쓰면 (a) 화면에 안 보이는 타이머가 되고, (b) 아이가 잠깐 자리를 비우면
난이도가 바닥으로 흐르고, (c) **4지선다 찍기를 숙련으로 오독한다** — 순수 추측으로
2연속 정답 확률이 1/16 이라 20문제 세션에서 기대 승급이 1.2회다.
**설명이 가장 필요한 아이의 시연이 짧아지는** 정확히 반대 방향이 된다.

### 완충 장치

1. 목표 가림%를 밴드 전체에 퍼뜨린다 — 가장 어려운 자리는 **한 마리에만**
2. 하락 직후 한 방은 더 쉽게 (`cushion`)
3. 새 축이 처음 켜지는 방은 나머지 축을 고정
4. 축 도입 간격 최소 3방 (E=13/20/24/28/32 — 어느 둘도 같은 E에서 시작하지 않는다)
5. 10탄 배수(축하 방)는 항상 `E − 3`

## 7. 형제 — 도감만 공용

**경쟁은 넣지 않는다.** 격차가 실력차가 아니라 **발달 단계차**라 순위를 붙이면 결과가
매번 고정되고, 고정된 순위는 경쟁이 아니라 낙인이다. 그리고 동생 쪽 결과가 항상 짐이
되므로 형제 순위표는 **게임오버 화면을 상시로 띄워 두는 것**과 같다.

**도감이 공용인 이유**: 형이 41탄에서 처음 만난 공룡이 동생 도감에도 들어오고, 동생이
우연히 찾은 종도 형 도감에 들어온다. **형의 실력이 동생에게 선물이 되고, 둘 중 누구도
지지 않는 유일한 진행이다.** 칸에 "누가 찾았는지"는 표시하지 않는다 — 그 격자가 곧 점수판이 된다.

**이미 안전했던 것**: 별과 최고 탄은 단조 갱신이라 동생이 형 프로필로 놀아도 내려가지
않는다. **유일한 예외가 `last_tier`** 였는데, 이어하기를 `next_tier()`(미클리어 최초 탄)로
바꿔 무해하게 만들었다.

## 8. 저장 — 하나의 파일, 여러 프로필

`user://rogame_save.json` (+ `.bak` 롤링). `math` 칸의 키 이름은 **옛 v2 저장 파일과
글자 그대로 같다** — 그래야 이관이 단순 복사가 되고, JSON 이 정수를 float 으로
돌려주는 문제를 재조립하는 기존 로직을 그대로 재사용할 수 있다. 새로 쓰면 `int()` 누락
버그가 반드시 난다.

`shell/migrate.gd` 는 **순수 함수**다 — 씬도 파일 접근도 없이 딕셔너리만 받고
딕셔너리를 돌려준다. 이관은 한 번 잘못되면 아이 기록이 사라지는 코드라 반드시
헤드리스로 전 경우를 돌려 볼 수 있어야 한다.

### 이관에서 물린 것 두 가지

1. **반쯤 쓰인 v3 파일을 v2 로 착각**하면 `stars` 가 빈 채로 이관이 "성공"해서
   아이 기록이 사라진다 → `_frog_v2()` 가 `schema`/`profiles`/`version>2` 를 보고 거른다.
2. **`use_custom_user_dir=true` 가 없으면 `custom_user_dir_name` 이 조용히 무시된다.**
   그러면 `config/name` 이 저장 폴더 이름이 되어, 앱 이름을 바꾸는 순간 기록이 사라진 것처럼 보인다.

### "이사 온 날"

옛 저장에는 종별 기록이 아예 없었다(정수 두 개뿐). 없는 것을 지어내지는 않되,
254마리를 찾은 아이에게 도감 0/50 을 보여 주면 **"예전 게임이 없어졌다"**로 읽는다.
셔플백이 50번마다 전 종을 한 바퀴 돌리므로 "전 종을 만난 적이 있다"는 통계적으로 참이다
→ 만난 것(회색)까지만 채우고 식구(컬러)는 앞쪽 몇 종만.

## 9. 검증

`tools/verify.sh` 하나로 모은다. **`ROGAME_NO_SAVE=1` 로 돌린다** —
예전에는 검사를 돌릴 때마다 저장 파일이 덮여서, "아이 기록"이라 믿던 값이 사실은
테스트가 만든 값이었다 (`found=254` = `--selftest` 를 두 번 돌린 값 127×2).
통합 앱에서는 저장이 하나라 공룡 기록까지 같이 오염된다.

### 감시하는 줄을 바꿨다

예전에는 `자리부족 0건` 을 안전 증거로 삼았는데, 그건 **동어반복이라 0 이외의 값이
나올 수 없었다** — `stage_room` 이 필요 마릿수를 자리 수에 맞춰 미리 깎기 때문이다.
지금은 **`want`(원한 마릿수) vs `count`(실제)** 를 센다. 이게 벌어지는 것이 진짜 신호다.

### 게임은 커맨드라인을 읽지 않는다

`--dump`/`--selftest` 는 `tests/dino_dump.tscn` 전용 진입점이 들고 있다.
게임이 읽으면 두 게임의 개발 도구가 인자를 섞고 `get_tree().quit()` 이 촬영 도중 앱을
죽인다. `verify.sh` 가 `grep -rn get_cmdline shell/ core/ games/` 로 강제한다.

### 헤드리스 함정

**SIGTERM 으로 죽이면 stdout 이 통째로 날아간다.** `timeout` 대신
`--quit-after <프레임>` 을 써라. 진단 print 가 안 보이면 대개 이것이다.

들어갈 수 있는 `.godot/` 가 통째로 커밋됐었다(누출은 없었다 — 확인함).
